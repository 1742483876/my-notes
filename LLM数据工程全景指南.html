Part 01

LLM 训练全流程 Pipeline

一个大模型从"白板"到"上线"，通常经历以下阶段。数据贯穿每一步。

1
预训练
Pre-training
在海量无标注语料上通过 Next Token Prediction 学习语言知识和世界知识。
数据量: 数万亿 Token 时长: 数周~数月
2
中间训练
Mid-training
在特定领域或长上下文语料上继续预训练，增强模型在垂直领域的能力。
数据量: 数百亿~万亿 Token 可选阶段
3
监督微调
SFT / Instruction Tuning
用高质量指令-回答对训练，让模型学会遵循人类指令。
数据量: 数万~百万条 质量 > 数量
4
强化学习对齐
RLHF / RLAIF / DPO
通过人类偏好或 AI 反馈对齐模型行为，提升安全性和有用性。
偏好数据 Reward Model
5
评估 & 部署
Evaluation & Serving
Benchmark 评测 + 红队测试 + 在线 A/B 测试，持续迭代数据飞轮。
Benchmark Red Teaming

Part 02

预训练数据 Pre-training Data

预训练是大模型的"基石"阶段，数据质量直接决定模型能力上限。

🌐

网页数据

Web Crawl Data

Common Crawl、自建爬虫获取的互联网文本。占预训练数据 60-80%。需经过去重、过滤、质量筛选。

📚

书籍 & 学术

Books & Academic Papers

高质量长文本来源，如 Books3、arXiv 论文、教科书。提升模型推理和知识深度。

💻

代码数据

Code Corpus

GitHub、Stack Overflow 等来源。提升模型编程和逻辑推理能力。The Stack、StarCoder 数据集。

🔬

合成数据

Synthetic Data

由强模型生成的训练数据。如数学推理链、代码解题过程。已成为 2024-2026 年的核心趋势。

Part 03

预训练数据处理 Pipeline 详解

从原始网页到高质量训练语料的完整处理流水线。每一步都有明确的技术目标和实现方法。

端到端数据处理 Pipeline（按执行顺序）

Extract → 🧹 规则过滤
Rule Filter → 🔄 MinHash
近似去重 → ⭐ 质量分
Quality Score → 🧠 语义去重
SemDedup → ✂️ 子串去重
SubstrDedup → ✅ 高质量
训练数据

1 网页解析抽取（Extract）

目标：从原始 HTML 中精准提取正文内容，去除非正文噪声。

技术方案：文本数据团队自研的网页解析模型，对每个 HTML 块（DOM 节点）进行「是否正文」二分类识别。不同于传统的规则方法（如 readability / trafilatura），这是一个基于模型的方案，准确率更高。

过滤目标：
  • 网页结构噪声：导航栏（nav）、侧边栏（sidebar）、底部备案信息（footer）、面包屑导航
  • UGC 噪声：论坛/评论中的发帖人信息、回复时间、用户签名、点赞数等元数据
  • 广告和脚本：广告区块、JavaScript 代码、CSS 样式内容
  • 模板重复内容：网站通用头部/底部、版权声明、免责声明

输入：原始 HTML / WARC 文件
输出：纯文本正文（保留段落结构）

2 规则过滤（Rule-based Quality Filter）

目标：用一系列确定性规则快速过滤掉明显的低质量文档，是成本最低、速度最快的过滤手段。

常用规则：
  • 超短正文过滤：正文字数过少（如 < 50 字）的文档直接丢弃，这类通常是残缺页面或导航页
  • 大段落重复检测：文章内部出现大段落多次重复（如 SEO 堆砌、模板生成内容）
  • 特殊字符比例：标点符号、emoji、数字占比过高的文档
  • 行级重复率：重复行数占总行数比例超过阈值
  • 语言检测：过滤非目标语言的文档（如只保留中文/英文）
  • URL/域名黑名单：已知的低质量站点、成人内容站点
  • 敏感词过滤：包含大量敏感/有害关键词的文档

特点：规则简单、执行速度极快，适合在 Pipeline 早期大批量过滤，降低后续环节的计算压力。

3 MinHash 近似去重（MinHash Deduplication）

目标：在海量文档中快速找到内容高度相似（但不完全相同）的文档并去重。

技术原理：
  1. 将每个文档切分为 n-gram（如 5-gram 字符片段）
  2. 对所有 n-gram 计算多个哈希函数，取每个哈希函数的最小值组成 MinHash 签名
  3. 使用 LSH（局部敏感哈希）将签名分桶，相同桶内的文档为候选重复对
  4. 对候选对计算 Jaccard 相似度，超过阈值则判定为重复

关键设计：
  • 跨源统一去重：此环节会将 Manpa（自建爬虫）和 Common Crawl 等不同来源的网页统一进行 MinHash 去重，避免不同数据源之间的重复
  • 阈值偏低策略：阈值会卡低一些（如 Jaccard ≥ 0.5 而非常见的 0.7-0.8），目的是多召回一些近似重复，宁可多去一点也不留冗余

规模参考：通常可去除 30-50% 的重复数据，是预训练数据去重的核心环节。

4 质量分筛选（Quality Scoring）

目标：用模型对每篇文档进行多维度质量打分，精细地筛选出高价值文本。

技术方案（两阶段）：
  1. LLM 打标：先用大语言模型（如 GPT-4 级别）对采样数据进行多维度质量标注
  2. 小模型蒸馏：用 LLM 标注的数据训练轻量级分类/回归模型（如 fastText / BERT-small），然后用小模型对全量数据打分

评估维度：
  • 文本知识性：内容是否包含有价值的知识信息
  • 连贯性：文本是否逻辑通顺、段落衔接自然
  • 教育意义：内容是否具有教育价值（类似 FineWeb-Edu 的思路）
  • 内容完整性：文章是否完整，非截断或残缺内容
  • 信息密度：单位文本中有效信息的浓度

过滤目标：去掉低文本价值的数据，如纯列表页、目录页、广告软文、无意义的 UGC 灌水帖等。
业界参考：FineWeb-Edu 使用类似方法，通过教育质量分筛选后的数据在下游任务上提升了 5-10%。

5 语义去重（Semantic Deduplication / SemDedup）

目标：去除文本表面不同但语义高度相似的重复内容——这是 MinHash 无法捕捉的。

典型场景：
  • 同一新闻事件的不同媒体报道（换了标题和措辞，但核心内容相同）
  • 同一知识点的不同表述（如多个百科站点对同一概念的解释）
  • 洗稿/伪原创内容（大量改写但信息无增量）

技术原理：
  1. 用预训练模型（如 BGE / E5 / OPT-125M）为每篇文档生成 Embedding 向量
  2. 对所有向量进行 K-Means 聚类，将语义相近的文档分到同一簇
  3. 在每个簇内，计算文档间的余弦相似度，去除高度相似的文档（保留一篇代表性文档）

核心价值：D4 论文（NeurIPS 2023）证明，在 MinHash 基础上再做语义去重，可以带来约 20% 的训练效率提升和 2% 的下游任务准确率提升。
计算成本：需要对全量数据做 Embedding 推理 + 聚类，是 Pipeline 中计算量最大的环节之一。

6 子串去重（Substring Deduplication / SubstrDedup）

目标：在文档内部检测和去除重复的文本片段，粒度比 MinHash（文档级）更细。

处理对象：
  • 模板文本：网站通用的版权声明、免责条款、联系方式等在多个页面中重复出现的文本块
  • 重复段落：文章内部因编辑错误或采集问题导致的段落重复
  • 跨文档公共子串：不同文档中共享的大段相同文本（如引用的法律条文、标准规范等）

技术方案：
  • 基于 Suffix Array（后缀数组）的高效子串匹配算法
  • 设定最小重复长度阈值（如 ≥ 50 字符），找到所有超过阈值的重复子串
  • 保留一份，去除其余重复出现

与 MinHash 的区别：
  • MinHash 是文档级去重：判断两篇文档整体是否相似
  • SubstrDedup 是片段级去重：在保留文档的前提下，去除文档内部或跨文档的重复文本片段
参考实现：Lee et al. (2022) "Deduplicating Training Data Makes Language Models Better" 中的 ExactSubstr 方法。

💡 Pipeline 设计哲学

渐进式过滤：从低成本到高成本，先用规则快速过滤大量垃圾，再用模型精细筛选。
多层去重：MinHash（文本相似）→ SemDedup（语义相似）→ SubstrDedup（片段重复），三层去重互补，覆盖不同类型的冗余。
跨源统一：不同数据源（自建爬虫、Common Crawl 等）统一进入同一个 Pipeline，避免源间重复。
质量优先：宁可多过滤一些数据（recall 略低），也要保证留下的数据质量足够高。

Part 04

中间训练 Mid-training

介于预训练和后训练之间的阶段，也称为 Continual Pre-training（CPT）或 Domain-Adaptive Pre-training（DAPT）。

💡 Mid-training 的核心价值

在通用预训练完成后，用领域特定数据继续预训练，使模型获得垂直领域的深度知识，同时保持通用能力。这是当前很多行业大模型（医疗、法律、金融、代码）的标准做法。

长上下文扩展

Long Context Extension

在长文档上继续预训练，配合 RoPE 频率调整（如 YaRN、NTK-Aware），将上下文窗口从 4K 扩展到 128K+。

领域适配

Domain Adaptation

注入领域语料（如医学文献、法律条文、金融报告），让模型掌握专业术语和领域推理模式。

多模态扩展

Multimodal Extension

在 mid-training 阶段引入图像-文本对、视频数据，训练视觉编码器与语言模型的对齐。

知识更新 / 退火

Knowledge Update / Annealing

用最新数据更新模型知识截止日期。Annealing（退火）阶段用高质量数据在低学习率下训练。

Part 05

后训练：监督微调 SFT

Supervised Fine-Tuning（SFT）是让"预训练模型"变成"对话助手"的关键步骤。

指令微调

Instruction Tuning

用 (instruction, response) 对训练模型遵循指令。FLAN、InstructGPT 开创了这一范式。核心是教会模型"你问我答"的对话格式。

对话数据

Conversational Data

多轮对话格式的训练数据。包含 system prompt、user、assistant 多角色。ShareGPT、UltraChat 是典型数据集。

思维链数据

Chain-of-Thought (CoT) Data

包含详细推理步骤的数据。让模型学会"先思考再回答"。对数学、逻辑推理任务至关重要。

工具调用数据

Tool / Function Calling Data

训练模型正确调用 API、函数、搜索引擎等外部工具。包含工具定义、调用参数、返回值解析。

⚡ SFT 数据的关键原则

质量远大于数量：LIMA 论文证明仅 1000 条高质量数据就能训练出优秀模型。
多样性：覆盖不同任务类型（问答、写作、代码、推理、翻译等）。
Decontamination：确保训练数据不包含评测集数据，避免"数据泄露"导致虚高分数。

Part 06

后训练：强化学习与对齐

通过人类偏好或 AI 反馈，让模型输出更安全、更有帮助、更诚实。

👤

RLHF

RL from Human Feedback

OpenAI 提出的经典范式。人类标注员对模型输出进行排序 → 训练 Reward Model → 用 PPO 优化策略模型。

🤖

RLAIF

RL from AI Feedback

用强 AI 模型替代人类标注员提供偏好反馈。Constitutional AI（Anthropic）是典型代表。大幅降低标注成本。

⚖️

DPO

Direct Preference Optimization

无需训练 Reward Model，直接用偏好对数据优化策略。更简单、更稳定。2024 年后成为主流方法之一。

🔥 2025-2026 年强化学习前沿方法

GRPO

Group Relative Policy Optimization

DeepSeek 提出。无需 Critic Model，通过组内相对奖励估计优势函数。在数学推理上表现优异，DeepSeek-R1 的核心训练方法。

DAPO

Dynamic Sampling Policy Optimization

ByteDance 提出。改进 GRPO 的采样策略，动态调整采样温度和过滤条件，解决训练中"熵塌缩"问题。

Rejection Sampling

Best-of-N Sampling

生成 N 个候选回答，用 Reward Model 选最优。简单有效，常与 SFT 结合使用。也叫 RFT（Rejection Fine-Tuning）。

RLVR

RL with Verifiable Rewards

用可验证的奖励信号（如数学题正确性、代码执行结果）替代人类偏好。DeepSeek-R1 和 Qwen3 的关键方法。

KTO

Kahneman-Tversky Optimization

基于行为经济学的前景理论，只需要"好/坏"二分标签而非成对偏好数据。降低数据标注门槛。

Online DPO / IPO

Online / Identity Preference Optimization

Online DPO 在训练中实时采样新数据对；IPO 修正了 DPO 的理论缺陷，使用更鲁棒的损失函数。

RLHF vs DPO vs GRPO 对比

方法Reward ModelCritic Model数据需求稳定性典型应用
PPO (RLHF)✅ 需要✅ 需要偏好对数据⚠️ 较难调参GPT-4, Claude
DPO❌ 不需要❌ 不需要偏好对数据✅ 稳定Llama 3, Zephyr
GRPO✅ 或规则奖励❌ 不需要Prompt + 规则✅ 稳定DeepSeek-R1
RLVR❌ 可验证奖励❌ 不需要带答案的题目✅ 稳定数学/代码场景

Part 07

主流数据方法论

数据工程中最核心的技术方法和最佳实践。

🧹

数据清洗 & 过滤

Data Cleaning & Filtering

规则过滤：URL 黑名单、长度过滤、特殊字符比例
模型过滤：用 fastText / BERT 分类器判断质量
困惑度过滤：用语言模型的 Perplexity 筛选
代表工具：CCNet, DataTrove, RedPajama pipeline

🔄

数据去重

Deduplication

精确去重：URL / Hash 完全匹配
模糊去重：MinHash + LSH（局部敏感哈希）
语义去重：Embedding 相似度去重
行级去重：去除重复的文本行/段落

🧪

合成数据生成

Synthetic Data Generation

Self-Instruct：模型自己生成指令和回答
Evol-Instruct：渐进式增加指令复杂度
Distillation：用强模型生成数据训练弱模型
代表项目：Alpaca, WizardLM, Magpie, Nemotron

⚖️

数据配比 & 课程学习

Data Mixing & Curriculum Learning

Data Mix：不同来源数据的比例调配（如 Web:Code:Book = 7:2:1）
Curriculum：从简单到复杂逐步训练
Annealing：训练末期用高质量数据"退火"
DoReMi：自动优化数据配比的方法

🏷️

数据标注

Data Annotation / Labeling

人工标注：专业标注员编写高质量回答
偏好标注：对比两个回答选择更好的
AI 辅助标注：用 LLM 初筛 + 人工审核
众包平台：Scale AI, Surge AI, 内部标注团队

🛡️

数据安全 & 合规

Data Safety & Compliance

PII 脱敏：去除个人身份信息
有害内容过滤：NSFW、暴力、仇恨内容
版权合规：尊重 robots.txt、许可证
Decontamination：去除评测集数据

Part 08

核心术语速查表

与领导对齐时常用的关键词和概念。

🎯 训练阶段
预训练Pre-training
在海量无标注数据上训练，通过预测下一个 Token 学习语言模式和世界知识。是模型能力的基础。
中间训练Mid-training / CPT
Continual Pre-training 的简称。在预训练后、SFT 前，用领域数据或长上下文数据继续训练。
后训练Post-training
预训练之后的所有训练阶段的统称，包括 SFT、RLHF、DPO 等。目标是让模型变得"可用"。
监督微调SFT (Supervised Fine-Tuning)
用人工标注的 (指令, 回答) 对训练模型。让模型从"续写文本"变成"遵循指令回答问题"。
指令微调Instruction Tuning
SFT 的一种形式，强调多任务指令格式。FLAN-T5、InstructGPT 是代表工作。
退火Annealing
训练末期用小学习率 + 高质量数据进行最后阶段训练。类似冶金中的"退火"过程，让模型更稳定。
🎮 强化学习 & 对齐
RLHFRL from Human Feedback
用人类偏好训练奖励模型，再用 RL（通常是 PPO）优化策略模型。ChatGPT 的核心训练方法。
RLAIFRL from AI Feedback
用 AI 模型替代人类提供偏好反馈。Anthropic 的 Constitutional AI 是典型代表。
PPOProximal Policy Optimization
最经典的策略梯度 RL 算法。通过限制策略更新幅度保证训练稳定性。RLHF 的标准优化器。
DPODirect Preference Optimization
绕过 Reward Model，直接用偏好对数据优化策略。将 RL 问题转化为简单的分类损失。
GRPOGroup Relative Policy Optimization
DeepSeek 提出，无需 Critic 模型，通过同组采样的相对奖励估计优势。DeepSeek-R1 的核心方法。
Reward Model奖励模型 (RM)
根据人类偏好训练的打分模型，用于评估模型输出的质量。是 RLHF 流程中的核心组件。
偏好数据Preference Data
形如 (prompt, chosen, rejected) 的三元组。标注员选择更好的回答作为 chosen，较差的作为 rejected。
对齐Alignment
让模型行为符合人类价值观和意图。核心目标：Helpful（有用）、Harmless（无害）、Honest（诚实）—— 3H 原则。
🔧 数据工程
Token / Tokenization分词
将文本切分为模型能处理的最小单元。BPE（Byte Pair Encoding）是主流方法。1 Token ≈ 0.7 个中文字。
去重Deduplication
去除训练数据中的重复内容。MinHash + LSH 是大规模去重的标准方法。可减少 30-50% 数据量。
困惑度Perplexity (PPL)
语言模型对文本的"困惑程度"。PPL 越低说明文本越"正常"。常用于过滤低质量数据。
数据配比Data Mix / Data Recipe
不同来源数据在训练中的比例。如 Llama 3: 网页 50% + 代码 25% + 书籍 15% + 数学 10%。
数据飞轮Data Flywheel
模型上线 → 收集用户反馈 → 改进数据 → 训练更好模型 → 更多用户 → 更多反馈。正向循环。
合成数据Synthetic Data
由 AI 模型生成的训练数据。2025 年已成为核心数据来源之一。关键是保证多样性和避免"模型塌缩"。
蒸馏Distillation
用大模型（Teacher）的输出训练小模型（Student）。是合成数据的一种重要形式。
数据污染Data Contamination
训练数据中包含了评测集的内容，导致评测分数虚高。Decontamination 是必要的数据处理步骤。
🏗️ 模型 & 推理
Scaling Law规模定律
模型性能与参数量、数据量、计算量的幂律关系。Chinchilla 定律指出数据量应与参数量匹配。
CoTChain-of-Thought
思维链推理。让模型逐步展示推理过程，显著提升数学和逻辑推理能力。
Reasoning Model推理模型
专门优化推理能力的模型，如 o1、DeepSeek-R1、QwQ。在回答前进行长链推理（thinking）。
MoEMixture of Experts
混合专家架构。每次推理只激活部分参数（专家），在保持大参数量的同时控制计算成本。
RAGRetrieval-Augmented Generation
检索增强生成。先检索相关文档，再让模型基于检索结果生成回答。减少幻觉的有效方法。
Benchmark评测基准
标准化评测集。常见：MMLU（知识）、GSM8K（数学）、HumanEval（代码）、MT-Bench（对话）。

📈 2025-2026 数据趋势

1. 合成数据成为主流：高质量真实数据接近枯竭，合成数据占比持续提升
2. RL 驱动的推理数据：通过 GRPO/RLVR 让模型自己"学会思考"，减少对标注数据的依赖
3. 多模态数据融合：图文、视频、音频数据统一训练
4. 数据质量 > 数据数量：FineWeb、DCLM 等项目证明过滤后的小数据集可以超越大数据集
5. Agent 交互数据：工具调用、多步推理、环境交互的数据成为新的关键数据类型
6. 数据飞轮闭环：线上反馈 → 数据改进 → 模型迭代的自动化闭环
