👥 大模型团队典型组织架构
一个完整的大模型团队通常包含 200-2000+ 人，分为 基础设施、数据、模型、对齐、评测、应用 六大核心方向。
下面以 业界主流一线团队（OpenAI / Anthropic / DeepSeek / Qwen / Meta AI）的公开披露为参考。

🏗️ 基础设施团队 (Infra)

• GPU 集群管理：千卡集群搭建、调度、故障恢复
• 分布式训练框架：3D 并行、通信优化、MFU 调优
• 存储与网络：高速文件系统、InfiniBand/NVLink
• MLOps：checkpoint 管理、实验追踪、自动化部署
👤 40-200人 · 占比 20-30%

📊 数据团队 (Data Engineering)

• 数据采集：网页爬取、PDF 提取、多语言语料
• 数据清洗：去重、毒性过滤、质量打分、配比优化
• 合成数据：用大模型生成高质量训练数据
• 标注管理：SFT/RLHF 人工标注、偏好对排、质检
👤 50-300人 · 占比 25-35%

🧬 模型团队 (Model / Research)

• 架构研究：Transformer 变体、MoE、Attention 优化
• 预训练：loss 监控、lr schedule、数据配比实验
• Scaling Law：参数量-数据量-算力最优配比
• 能力增强：长上下文、推理能力、代码/数学强化
👤 30-100人 · 占比 15-20%

🎯 对齐团队 (Alignment)

• SFT：指令微调、对话格式训练
• RLHF/DPO：Reward Model、PPO/GRPO 训练
• 安全：Red Teaming、拒答策略、有害内容过滤
• 推理增强：CoT、o1/R1 范式的强化学习训练
👤 20-80人 · 占比 10-15%

📈 评测团队 (Evaluation)

• Benchmark：MMLU、HumanEval、MATH、C-Eval
• 人工评测：Chatbot Arena、人类偏好评分
• 安全评测：毒性检测、偏见测试、对抗攻击
• AB Test：线上灰度、用户反馈闭环
👤 10-40人 · 占比 5-10%

🚀 应用与推理团队 (Serving)

• 推理优化：量化(FP8/INT4)、KV Cache、FlashAttention
• 模型蒸馏：大→小蒸馏、推理链蒸馏
• API 服务：高并发、负载均衡、cost-per-token 优化
• 产品集成：Agent、RAG、Function Calling
👤 20-80人 · 占比 10-15%
💡 核心洞察：
• 数据团队占比最大（25-35%），这与直觉不同——大模型的能力上限由数据决定
• Infra 团队是隐形基石，千卡训练的稳定性直接决定几千万美金是否打水漂
• 对齐团队工程复杂度最高，虽然算力占比小，但链路最长：数据→RM→PPO→评测→反馈

📚 预训练 (Pre-training) 深度解析

🎯 核心目标：Next Token Prediction

给定文本前缀，预测下一个 token。损失函数是标准交叉熵。
目标极其简单，但工程挑战极其复杂。

输入: "The cat sat on the"
目标: 预测下一个 Token 是 "mat" (概率最高)

模型通过最小化交叉熵损失来学习语言：
L = -Σ log P(x_t | x_1, x_2, ..., x_{t-1})

📊 数据工程：预训练的第一战场

数据出错一轮，损失的是几千万美金。以 Qwen 系列为例：

版本Tokens关键进化
Qwen 1.03T基础多语言语料·MinHash+LSH去重·规则+ML过滤
Qwen 2.07T用 Qwen1 作过滤器·合成数据·30种语言·代码/数学加量
Qwen 2.518TQwen2-Instruct做多维打分·领域专家数据融合·数据分布重构(下采样低质域/上采样高质域)
Qwen 336T119种语言·Qwen2.5-VL提取PDF·合成教科书/QA/代码

数据清洗 7 级流水线（以 DeepSeek-V3 为参考）：

  • ① 原始去重（MinHash/SimHash）
  • ② 低质量过滤（标点比例/字符长度/规则）
  • ③ NSFW 过滤（暴力/色情/有害）
  • ④ 基于模型的质量打分（用前代模型当评委）
  • ⑤ 领域识别与分类
  • ⑥ 数据配比优化（小模型实验验证最优比例）
  • ⑦ 最终采样 & Tokenization（BPE/SentencePiece）

⚙️ 分布式训练：3D 并行

并行策略核心思想适用场景
数据并行 (DP)每张 GPU 一份模型副本，各自处理不同数据，梯度同步模型放得下单卡
张量并行 (TP)把一个矩阵运算拆到多张 GPU 上单层太大，放不下一张卡
流水线并行 (PP)不同层放在不同 GPU 上，数据像流水线一样流过层数太多
ZeRO (1/2/3)优化器状态/梯度/参数分片存储内存优化
序列并行 (SP)把长序列拆分到多 GPU 处理长上下文训练

实际配置示例：训练 70B 模型，256× H100 集群
→ TP=8（8卡拆一层）× PP=4（4组流水线）× DP=8（8份数据并行）

🔥 预训练工程四大挑战

  • ① 数据够不够、干不干净：13T tokens 的预训练，数据出错一轮 = 几千万美金打水漂
  • ② 训练稳不稳：loss spike、NaN、grad norm 爆炸 → checkpoint + 回滚 + 跳 batch
  • ③ 吞吐能不能打满：3D 并行 + 通信重叠 + FP8/BF16 混合精度 → MFU 从 30% 抠到 50%+
  • ④ 故障能不能容忍：千卡训练几十天，单卡 MTBF 几千小时 → 每天都有卡挂 → 自动检测 + 替换 + 恢复

🎯 Mid-train / 继续预训练 (Continued PT)

💡 核心理念：用 5-10% 额外算力，换取显著能力跃升

Mid-train 是 2024 年后越来越标准化的训练阶段。在 base model 快训完时，调整数据配比，大幅加权 数学、代码、STEM、推理 类数据，同时扩展上下文窗口。

为什么需要 Mid-train？
预训练语料以网页为主，数学/代码/推理数据占比天然不足。Mid-train 就是在不重新花一遍预训练钱的前提下，定向补强弱势能力。

📋 各家 Mid-train 实践

模型Mid-train 做了什么效果
Qwen3S1: 30T通用 → S2: 5T加码STEM/代码/推理 → S3: 长上下文32K三阶段递进，逐步强化
DeepSeek-V3后期把上下文从 4K → 32K → 128K，配合 YaRN长文本能力飞跃
Qwen2.5大幅提高代码/数学数据占比，融合 Qwen2.5-Math/Coder 数据MATH/HumanEval 分数大幅上升
LLaMA-3.1Annealing 阶段：降低 lr、换数据配比、刷高质量数据128K 上下文支持

🧪 Mid-train 的关键技术

  • 数据配比调整：数学/代码从预训练的 5-10% → Mid-train 的 30-50%
  • 长上下文扩展：
    • RoPE 频率调整（NTK-aware / YaRN / Dynamic NTK）
    • 渐进式扩展：4K → 8K → 32K → 128K → 1M
    • 长文本数据注入（书籍、代码仓库、学术论文全文）
  • 学习率策略：通常从预训练末尾的 lr 继续，或用 cosine decay 缓降
  • 领域专家数据融合：将 Math-Instruct / Code-Instruct 模型生成的高质量数据混入

📊 资源消耗

  • Tokens：500B ~ 5T
  • 算力占比：预训练的 3-8%
  • 时间：几天到几周
  • GPU：与预训练同集群

🎯 核心产出

  • ✅ 数学/推理/代码能力显著提升
  • ✅ 长上下文支持（32K→128K+）
  • ✅ 为下游 SFT 提供更强底座
  • ✅ 性价比极高（小投入大回报）
🎓 后训练 (Post-training)
后训练 = SFT（教模型听话）+ Alignment（教模型什么是好的回答）
算力占比小（<5%），但工程链路最长、人力投入最大。

📝 第一步：SFT（监督微调）

目标：让模型从「续写模式」切换到「指令遵循模式」

预训练模型：你问「北京有什么好吃的？」→ 它续写「北京有什么好玩的？上海有什么好吃的？」
SFT 之后：你问「北京有什么好吃的？」→ 它回答「北京烤鸭、炸酱面、豆汁儿...」
维度详情
数据格式(指令, 回答) 对 / 多轮对话
数据量数十万 ~ 数百万条（10M ~ 1B tokens）
训练方式全参微调 或 LoRA/QLoRA（参数高效微调）
关键技巧Chat Template 格式对齐、数据质量>数量、Packing 提升吞吐
耗时几小时 ~ 几天
算力8-64× GPU，预训练的 <1%

⚖️ 第二步：Alignment（对齐）

目标：让模型的回答有用 (Helpful)、无害 (Harmless)、诚实 (Honest)

方法核心思路优缺点
RLHF (PPO)训练 Reward Model → PPO 策略优化
需要：SFT模型 + RM + PPO Actor/Critic		上限最高但复杂，吃显存，超参敏感
DPO不用 RL，直接在偏好对 (chosen, rejected) 上做对比损失训练稳定、成本低，开源社区主力
GRPOGroup Relative Policy Optimization
DeepSeek-R1 核心方法		适合推理增强，不需要 RM
KTO只需要好/坏标签，不需要成对偏好数据需求最少
RLAIF用更强 LLM 做 Reward，替代人工标注便宜但有偏差（LLM 自己对齐自己）

🧠 推理增强训练（o1/R1 范式）

2024-2025 年最重要的突破：让模型学会「思考」，而不仅仅是「回答」。

  • 核心思路：用 RL（GRPO/PPO）训练模型生成 Chain-of-Thought，奖励正确推理过程
  • 代表模型：OpenAI o1/o3、DeepSeek-R1、Kimi K1.5
  • 关键技术：
    • Rule-based Reward：格式正确性 + 答案准确性（简单稀疏奖励即可）
    • Process Reward Model (PRM)：对推理过程每一步打分
    • 推理蒸馏：把大模型的思维链蒸馏给小模型（DeepSeek-R1 → 7B/14B/32B）
DeepSeek-R1 训练路径：
① 671B MoE base → ② GRPO 大规模 RL 训练（数学/代码/推理奖励）→ ③ 模型学会 CoT 推理 → ④ 蒸馏到 Qwen/LLaMA 7B~32B

🏗️ 组合式多模态架构（当前主流）

┌─────────────┐ ┌──────────┐ ┌──────────────────────┐ │ 图像/视频 │ │ Projector│ │ 预训练 LLM │ │ │──→ │ (MLP) │──→ │ (Qwen/LLaMA/...) │──→ 文本输出 │ Vision │ │ 映射到 │ │ 把视觉token当作 │ │ Encoder │ │ LLM空间 │ │ 特殊文本token处理 │ │ (ViT/CLIP) │ │ │ │ │ └─────────────┘ └──────────┘ └──────────────────────┘ ↑ 预训练冻结 ↑ 预训练冻结或微调 (CLIP/SigLIP/EVA) (解冻全部或仅MoE Expert)

典型训练流程（3阶段）：

  • Stage 1 - Projector 预训练：冻结 Vision Encoder + LLM，只训练 Projector（百万级图文对）
  • Stage 2 - 多模态预训练：解冻部分/全部参数，在大规模图文数据上训练对齐
  • Stage 3 - 指令微调：用高质量多模态指令数据做 SFT

🧬 原生多模态架构（前沿方向）

核心区别：Vision Encoder 不是冻结的外挂，而是和 LLM 一起从头训练或联合优化。

┌─────────────────────────────────────────────────────────────┐ │ 统一 Transformer │ │ │ │ 图像 → ViT Encoder ─┐ │ │ ├─→ 统一序列 → Transformer Layers → 输出│ │ 文本 → Tokenizer ───┘ (视觉token + 文本token混合) │ │ │ │ ⭐ MoE: 视觉专用Expert + 文本专用Expert + 共享Expert │ │ ⭐ 端到端联合训练，Vision Encoder 权重也在更新 │ └─────────────────────────────────────────────────────────────┘
NaViL 的关键发现（NeurIPS 2025）：
① 从预训练 LLM 初始化显著加速多模态收敛（优于完全从头训练）
② MoE 架构（视觉专用 + 语言专用 Expert）显著提升性能，不增加推理成本
③ 视觉编码器的最优规模与 LLM 规模成对数线性关系——应该联合缩放！
④ LLM 扩大持续提升性能，但视觉编码器扩大有递减收益（被 LLM 容量限制）

🔑 关键组件详解

组件作用主流选择
Vision Encoder将图像编码为视觉特征向量ViT、CLIP ViT-L、SigLIP、EVA-CLIP
Projector将视觉特征映射到 LLM 的 embedding 空间MLP (2层)、Cross-Attention、Perceiver Resampler
Visual Tokenizer将图像离散化为 token（用于理解+生成统一）MoVQGAN、VQGAN、MingTok
MoE Expert模态专用 Expert 处理异构数据视觉 FFN Expert + 文本 FFN Expert + Attention Expert

🌐 前沿统一架构：理解+生成一体化

  • Transfusion：在单个 Transformer 中同时处理离散文本 token 和连续图像向量
  • Emu3：把图像也转成离散 token，所有模态统一做 next-token prediction
  • Janus-Pro (DeepSeek)：解耦理解和生成的视觉编码（理解用高维语义特征，生成用低维像素码）
  • NaViL：MoE + 原生端到端训练，支持任意分辨率图片
多模态对齐训练方法：
• 对比学习（CLIP 范式）：拉近配对图文、推远非配对图文
• 生成式预训练：在图文交替序列上做 Next Token Prediction
• RL 对齐：MM-RLHF / Vision-R1 / MM-Eureka — 用 GRPO/DPO 提升 VLM 推理能力

  • 节点内互联：NVLink/NVSwitch — 8卡 H100 全互联 900 GB/s
  • 节点间互联：InfiniBand HDR/NDR — 400-800 Gbps
  • 存储：GPFS/Lustre 并行文件系统 — 100+ GB/s 聚合带宽
  • 规模：千卡训练集群 = 100-500 个节点 × 8 GPU/节点
故障率：千卡集群训练几十天，单卡 MTBF 约几千小时 → 平均每天 1-3 张卡故障
必须有自动故障检测、热替换、checkpoint 恢复机制。
